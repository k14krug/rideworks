## 6. Source and numerical rules

**MMP definition:** At exact duration `d` seconds, find the maximum arithmetic-average power among every fully supported consecutive `d`-second (or corresponding supported 1 Hz observed) window in the chosen activity; across a period, choose the maximum eligible ride result for each `d`. Do not use peak-sample watts as a 5s average, NP/TSS/HR/FTP/estimated session score, interpolation-filled gaps or post-hoc min/max summary power.

**Source policy:** Reuse current **Virtual Ride** source classification, file precedence, API fallback restrictions and preservation/provenance. Duration eligibility is not identical to 20-minute eligibility: an otherwise trusted file may support a complete **15-second** window without supporting a **1,200-second** one. Support such short-duration evidence rather than excluding it just because `performance_history.eligible` is false, while preserving the rule that an API source cannot bypass file watt evidence merely because that file lacks a 20-minute eligible window. Multiple competing candidate sources remain ambiguous until supported selection is defensible. Do not silently admit outdoor measured watts, fabricated estimated watts, unsupported recorded power or incomplete API sample pairing.

**Continuity:** Current accepted 20-minute calculations require strict one-second adjacent timestamps and nonnull nonnegative watts. Reuse this for all durations, including timer boundaries and contradictory/stopped intervals where verified native timer evidence matters. Zero is a valid watt reading. A missing sample can invalidate spanning windows but not supported shorter windows elsewhere. No gap repair, resampling, pause stitching or guesswork in PC-01 without explicit Analyst/Owner evidence decision. For an unsupported long duration, show unavailable and terminate the plotted curve segment.

**Parity:** Every shared qualifying source at 1,200 seconds must match the accepted native/API best-20 computed value, raw and display rounding/earliest-tie semantics. The accepted `performance_history` table and `best-average-power-v1` behavior may **not** be changed as a shortcut for curves. No W/kg until dated weight evidence is reliable.

**Performance:** Naive every-duration-for-every-ride `O(n²)` full-curve scanning may be unacceptable for ~1,000 long rides. Choose a practical versioned set of evaluated durations, with enough density to visually resolve the power-duration profile including 1s/short intervals, 5/20-minute and long efforts, while documenting which values are *actually* calculated. Do not return hover values from merely interpolated line segments as exact. Use the simplest reproducible cached per-activity derived profiles, source/extraction signatures, and local rebuild or incremental sync path that avoids reloading every raw recording on chart page views. Do not introduce generic analytics infrastructure or per-sample data duplication. Validate elapsed compute/runtime with actual cohort; discuss explicit tradeoff if display resolution or duration upper bound seems inadequate.

**Period semantics:** Presently Performance may be anchored to the page's current instant and current rider-local calendar for years; historic Activity always anchors its previous 42 days to activity start. No future leak, even when the historical selected ride came from a day with another later ride; cohort membership and time boundaries must be deterministic and documented.

### 13.1 Controlling MMP evidence and endpoint meaning

- **Primary PC-01 MMP evidence is the accepted Performance-style observed 1 Hz sample/timestamp sequence.** A qualifying window contains exactly `d` nonnull, nonnegative integer watts at strictly one-second adjacent valid absolute timestamps (or validated one-second API offsets). Zero is valid. Missing samples or broken timestamps invalidate spanning windows. Never interpolate, impute stopped-time zeros, resample, shift observations or stitch separated runs to obtain a longer `d`-second window.
- **FIT record timestamps identify observations, not half-open forward one-second bins controlled by timer stop timestamps.** If a valid nonzero source-power sample occurs **exactly at** a verified timer stop timestamp, **admit that endpoint sample** into the preceding active interval for MMP purposes. A 1,200-s window may therefore end at that sample if its 1,200 observed record times are consecutive; the last sample time and `end_exclusive_timestamp` retain their existing accepted semantics. A stop event is **not** an instruction to discard the same-timestamp observation. This is PC-01's recorded-sample semantics; do **not** modify P4-02 stress/active-time integration's separate half-open one-second-bin convention.
- When `timer_scope(events, session)` returns **independently verified** active intervals, use inclusive observation endpoints `start <= sample_timestamp <= stop` for grouping, while prohibiting windows **across distinct verified active intervals**. Keep groups distinct even if a stop and subsequent start share a timestamp; deterministically assign at most one group and never make that a license to stitch two separate runs. If the observed series naturally has a one-second gap across a stop, that alone already splits continuous windows. Endpoint inclusion cannot manufacture a timestamp or watt reading.
- Do not assume every recorded watt at a source's last stop is an additional one-second timer duration. MMP counts observed samples under the accepted Performance contract, not reconstructed active timer seconds or kilojoule integration.

### 13.2 Paired but contradictory / unverified timer evidence

- The current `timer_scope()` distinguishes mere **paired** events from intervals **corroborated by FIT session timing and active-duration metadata**. This is important: 981/1,020 paired scopes in the preflight were *not whole-session verified*, for multiple possible reasons. **Do not exclude all these rides or use unverified start/stop bounds as hard clipping masks.**
- Where FIT timer/session evidence is missing, unverified or materially **contradicts continued valid recorded power**, derive PC-01 MMP **only from qualifying consecutive recorded watt observations**, consistent with `best-average-power-v1`; **do not clip at unverified stop events, infer that power samples are fabricated, extend paused segments or claim the resulting windows are verified active-time efforts**. This retains the 127 post-stop observations as *observed* evidence rather than interpreting the contradicting timer event as proof that they should be erased.
- Preserve and expose a **small, versioned, source-level provenance/limitation indicator**, e.g. `recorded_sample_timeline; timer_scope_unverified`, and a specific **timer/source discrepancy** if corroborated disagreement actually affects an evaluated effort. Surface such information in inspectable provenance/details rather than repeat a frightening general warning on every curve/card. An otherwise valid result is still a **calculated observed power** best, *not* a session-verified active interval. Never assert that an unverified timer event confirms riding or that a bare paired event makes every observation active.
- Verified timer pause and unverified conflicting session metadata are **different conditions**: the first can segment an MMP calculation; the second is not grounds to disqualify all otherwise valid observed power or silently substitute a different 20-minute method. Distinguish `timer events absent`, `unpaired/invalid`, `paired but scope unverified`, `session-verified`, and `material discrepancy` as evidence permits, without requiring dozens of rider-facing flags.
