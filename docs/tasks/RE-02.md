# RE-02 — Verify Relative Effort UI and integrate the accepted feature into main

**Status:** pending — Analyst-authored JIT, 2026-10-29.
**Starting point:** refreshed `main`. **Feature reference:** `dev`, where `relative-effort-v1` and its UI exist. **Target:** a focused task PR against `main`, not a merge of all `dev`.

## 1. Purpose

Complete the already-implemented Relative Effort feature: verify colored ride indicators on Home, Activities and Activity Review, then integrate the approved behavior into the current `main` application without losing more recent accepted Home/UI features. This is integration and verification, **not a redesign or recalibration project**.

## 2. Background and explicit Owner decision

The Owner recalled an effort-color dot on the Home Recent Activities card and a comparable Activities display. Source inspection confirmed these are implemented on `dev`:
- `rideworks/relative_effort.py` — shared `relative-effort-v1` calculation, `chip()`, `card()`.
- `rideworks/home.py` — colored dot in Recent Activities title link.
- `rideworks/web.py` — Activities Relative Effort column and Activity Review card.
- `rideworks/static/style.css` — five effort colors and neutral unavailable state.
- `tests/test_rideworks_relative_effort.py` and relevant browser verification scripts.

The Owner's **2026-10-29 final calibration decision** (recorded on [PR #52](https://github.com/k14krug/rideworks/pull/52)): nearly all indoor rides have power; outdoor rides generally lack power. Comparisons between power-based and HR-estimated stress will necessarily be imperfect, and that is acceptable. **Use the existing mixed-source algorithm as-is**; adjust only later if actual use shows a need. This supersedes older RE-01 notes calling for pre-release calibration experiments. The [PR #52 sensitivity audit](https://github.com/k14krug/rideworks/blob/review/re-01-calibration-audit-20261029/docs/reviews/2026-10-29-re-01-relative-effort-audit.md) is background research, not an integration dependency or blocker.

`dev` and `main` have diverged. `main` now includes accepted HOME-UI-02 and HOME-UI-03 work that may be absent from `dev`. Do **not** merge `dev` wholesale, reset branches, or replace the present Home page with its older `dev` template.

**Accepted feature semantics (preserve exactly):** Cycling rides are categorized from selected modeled whole-workout stress and corresponding supported active duration, relative to eligible rides in the **preceding 42 America/Los_Angeles calendar days** (not same day), with **at least six** comparison rides. Use empirical midrank percentile quintiles for training load and stress per supported active hour; overall category begins with load and rises only one band when intensity is at least two bands higher. Labels: **Very Light** (teal green), **Light** (green), **Moderate** (blue), **High** (amber), **Very High** (muted red); **Not rated** (neutral gray) for insufficient or ineligible evidence. Keep measured/estimated source distinctions and history-relative meaning; this is not absolute exertion, RPE, or a physiological severity score.

## 5. Scope / implementation

1. Confirm current Git refs, clean worktree and task lifecycle. Compare current `main` to `dev` for **only** Relative Effort and its necessary page/transaction/style/test dependencies. Record a short integration plan in task evidence. Do not assume old SHAs remain current.
2. Verify the source feature on `dev` with available relevant tests and browser behavior. If no dev server is running, use an isolated temporary loopback server and a disposable compatible Store copy as permitted; **do not restart an existing service** or modify the authoritative Store just to create a test environment.
3. Bring the shared Relative Effort calculation and its **minimal necessary support** into the current `main` app. Preserve `relative-effort-v1` exactly. If a needed helper/dependency is already compatible on `main`, reuse it instead of copying `dev` wholesale.
4. Integrate consistent classification and visual semantics into:
   - **Home / Recent Activities:** small colored dot beside ride title, with an accessible name/title describing the effort; preserve all present Home layout, Mileage by Year/trend/goal behavior and counts.
   - **Activities:** readable Relative Effort dot **and text** column for each eligible ride; preserve sorting, paging, filters, activity details links, source fields and tablet/mobile readability.
   - **Activity Review:** the accepted **compact**, subtly accented Relative Effort card with load/intensity categories, an optional expandable explanation, and neutral unavailable state.
5. Preserve the necessary `dev` concurrency and responsive-layout corrections when adapting code to current `main`: Home GET must not acquire an early SQLite writer lock while expensive read/Plan work continues; keep cache signature validation, coherent snapshots, and rollback/retry semantics. Avoid duplicate history scans if an already-safe simple request-local reuse is possible, but do not invent caching infrastructure.
6. Add/adapt focused unit and browser assertions, rather than copying historical tests without checking whether their context still applies.

**If the feature cannot be integrated without a broad import of unrelated `dev` work, a schema/data migration, or conflicting accepted main designs:** stop with a concrete dependency map and minimal alternatives for Analyst/Owner decision, **before** implementing the broad change.
