## Required behavior
- On Segments, provide Add segment by pasting a Strava activity-effort link from the rider’s Zwift activity. Validate the link and use its exact activity and effort IDs with the documented authenticated activity-detail endpoint. Verify that the exact returned effort belongs to the activity and connected athlete, derive the watched segment from the nested segment ID, and save the effort with its elapsed time. Do not treat the URL suffix as the segment ID, round IDs, fetch arbitrary user-supplied URLs, or create a watch entry on a failed lookup. Let the same flow save another selected older effort for an already watched segment without duplicating it. Explain that a standalone segment link is not supported in this release.
- Save the rider’s own verified watched efforts durably with Strava provenance, effort identity, elapsed time, date and source activity ID. Link to the RideWorks ride only when deterministic and unique; preserve otherwise valid unmatched efforts and link when an exact unique match becomes available. Deduplicate by exact effort ID, retaining distinct attempts on the same ride. The Owner accepts the API access risk; personal use is not an exemption from Strava API Policy §§5.5 and 6.2. No raw response retention required.
- Extend the shared Home/Admin manual Sync to check newly synced Zwift rides for watched efforts using activity detail with include_all_efforts=true. Reuse qualifying detail already fetched when available. With an empty watchlist do not add detail calls. Define eligible new rides from the existing sync path; do not scan pre-existing rides to populate the watchlist. Use a bounded per-Sync budget and retain pending failed or deferred ride checks for later manual Sync, including when no new rides arrive. A successful complete response with no matches is not a failure; do not mark a failed, invalid, or incomplete lookup as checked. Stop additional segment requests on rate limit or authorization failure and report pending work. Keep successful ride imports and saved efforts intact on segment failures; show a partial result in both entry points and preserve existing Sync protections and Home new-ride alert behavior.
- Show saved dated history and fastest saved effort without calling Strava. Explain that history starts with saved efforts and is not a complete Strava history. On Home → Recent Rides and Activities, show a link such as “2 tracked segments” when saved matched results exist, counting distinct watched segments, not attempts. Omit zero. Open Segments filtered to that ride with its saved attempts and a clear route back to the watchlist. Use local data only for these displays.
