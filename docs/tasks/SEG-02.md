## Required behavior
- Add **Import history** for one already watched segment at a time. Offer **From Strava** and **Paste My Results**; preserve normal Sync and Add segment behavior. Preview counts and warnings before writing. Protect actions using existing origin, nonce, and operation controls. Limit input and requests; no background jobs.
- API path: use the documented subscription-required List Segment Efforts endpoint for the connected athlete and selected segment, exact integer IDs, 100 per request and a firm budget of at most five reads per import attempt. Use documented local date bounds to split capped windows when useful; overlap boundary safely and deduplicate by exact effort ID. Check that bounded responses honor their bounds before using them as coverage evidence. If a window stays capped, fails, or cannot be verified, show that history may be incomplete; never claim full Strava history from a partial response. Stop further reads on rate or authorization failure. On 404 offer paste, not “no efforts.” Save only validated athlete/segment/effort/activity IDs, dates and elapsed times using existing saved-effort semantics. Apply the Owner's existing durable retention decision; do not treat it as a Strava terms exemption.
- Paste path: select the watched segment explicitly. Parse the demonstrated Markdown table fragments with linked dates plus ordinary tabular text when unambiguous, ignoring optional speed, HR, power and athlete fields. Support multiple rows/fragments and date plus displayed duration without an activity link. Do not fetch links. Preserve calendar date and displayed time with user-imported Strava provenance; do not invent timestamps or API elapsed semantics. Map exact activity IDs to local rides only on a unique established match. Preview unparsed rows without guessing; allow saving valid rows in one confirmation.
- Automate replay and exact-ID duplicate handling. Same normalized paste batch is idempotent (ignore formatting noise; preserve multiplicity within a batch); overlapping batches use stable evidence, not rank or position. When only activity ID is available, same segment and ride plus same displayed duration or a matching API elapsed candidate is a possible overlap, not proof. Do not silently merge a possible overlap or make the user inspect every row. Put only uncertain overlaps in an exception group, default to leaving those rows unimported with an explicit count, and let the user keep separate or confirm an already-saved match. For rows without a ride ID, a date and duration match is only a candidate; preserve genuinely distinct same-ride attempts and provenance. Apply the same no-silent-merge rule when Sync later supplies an exact effort; avoid counting known confirmed matches twice. Show saved count, source, best saved time, and no complete-history claim. Keep distinct tracked-segment ride counts and offline display working.
